# سیاست نگهداری تاریخچه Import و خطاها

## وضعیت فعلی

در وضعیت فعلی سیستم، batchهای import و error history به صورت خودکار حذف نمی‌شوند. این تصمیم برای حفظ قابلیت rollback، بررسی خطاهای import، و امکان ممیزی تغییرات داده است.

## اصل‌های عملیاتی

- آخرین batch موفق هر source نباید حذف شود.
- batch فعال فعلی هر source نباید حذف شود.
- batch هدف rollback یا batchهایی که در history به آن‌ها اشاره می‌شود نباید بدون بررسی حذف شوند.
- error history تا زمان تعریف job پاکسازی کنترل‌شده حفظ می‌شود.
- حذف خودکار بدون backup خطرناک است، چون ممکن است امکان rollback، تحلیل خطای import، یا بررسی اختلاف داده از بین برود.

## پیشنهاد نگهداری برای آینده

- batchهای موفق هر source حداقل برای چند دوره import نگهداری شوند.
- errorهای import برای مدت مشخص، مثلا ۹۰ تا ۱۸۰ روز، نگهداری شوند؛ مقدار دقیق باید با نیاز عملیاتی و حجم داده تعیین شود.
- پاکسازی فقط با job کنترل‌شده backend انجام شود، نه با حذف دستی یا endpoint عمومی.
- قبل از purge، backup دیتابیس یا snapshot قابل اتکا گرفته شود.
- purge باید dry-run داشته باشد و تعداد batch/error/rowهای قابل حذف را قبل از اجرا گزارش کند.
- purge نباید آخرین batch موفق، batch فعال، یا batchهای درگیر در زنجیره rollback را حذف کند.

## پیشنهاد command یا endpoint آینده

فعلا چیزی پیاده‌سازی نمی‌شود. برای آینده می‌توان یک command مدیریتی مثل نمونه زیر طراحی کرد:

```text
flask imports purge-history --source <source> --older-than-days <days> --dry-run
```

اگر endpoint لازم شد، باید فقط برای admin فعال باشد، audit کامل داشته باشد، و ابتدا حالت preview/dry-run ارائه کند.

## ریسک حذف زودهنگام

حذف زودهنگام batch یا error history می‌تواند باعث این مشکلات شود:

- از دست رفتن امکان rollback به آخرین وضعیت سالم
- ناممکن شدن بررسی علت خطاهای import
- از دست رفتن شواهد audit و پاسخ‌گویی عملیاتی
- سخت شدن مقایسه batchهای قبلی و جدید

## تصمیم فعلی

تا زمان طراحی و تست job پاکسازی، هیچ purge خودکاری انجام نمی‌شود و history حفظ می‌شود.
